# Owned Post Learning

Use this when the user asks to learn from a post the skill just drafted, draft-saved, or published. This is different from influencer scanning: owned-post lessons can improve the next run immediately, but do not become durable `style-memory.md` entries until repeated or supported by performance data.

## Inputs

Review:

- final title, body, tags, category or Naver topic,
- visual storyboard and actual editor/public image result,
- publication receipt or draft evidence,
- user correction after the run,
- any editor mistakes that almost caused bad output.

Do not store account identifiers, login data, browser state, screenshots with private details, or creator-specific imitation notes.

## What To Learn

Extract only transferable patterns:

- title shape,
- first-screen promise and caution,
- paragraph rhythm,
- table or checklist placement,
- source and checked-date handling,
- visual roles and captions,
- tag/category choice,
- editor transfer failure and recovery pattern.

Classify each lesson:

- `candidate`: useful in the next run but not performance-proven,
- `durable`: repeated across owned results or supported by metrics,
- `reject`: caused confusion, duplication, weak trust, or editor risk.

Only `durable` lessons may be copied into `style-memory.md`.

## 2026-07-07 Revenue Strategy Post Candidate

Source: owned Naver public post and Tistory draft canary about AdSense monthly revenue strategy.

Candidate writing patterns:

- Title pattern: specific revenue goal + current year + realistic condition, not a guarantee.
- Opening pattern: common claim, conditional agreement, clear caveat, why it matters now, and a bounded promise.
- First-screen pattern: "not only traffic" plus a short decision checklist.
- Body pattern: trust first, then search intent and mobile UX, then revenue diversification, then policy risks, then realistic operating order.
- Trust pattern: checked date and official source names near the source section.
- Closing pattern: give one practical editorial question for the next post, not a motivational slogan.

Candidate visual patterns:

- For blog monetization, SEO, AdSense, and operations topics, avoid money-pile, luxury, jackpot, or guaranteed-income visuals.
- Prefer operator-view scenes: analytics review, content planning desk, source-checking workflow, or neutral roadmap diagram.
- Use a diagram only when it reduces a real decision; keep Korean text visually checked at original resolution.

Rejected patterns:

- Do not repeat monetization strategy paragraphs from generic summaries.
- Do not include unsupported exact CPC averages, guaranteed revenue, or fake personal earnings.
- Do not make text cards the default thumbnail.

Next-run use:

- Use this as a candidate template for information posts about AdSense, blogging, SEO, online side income, and platform policy.
- Hold durability until 24-hour, 72-hour, and 7-day results show whether the title and first-screen structure work.

## 2026-07-07 Tistory Editor Incident

Incident:

- First Tistory image paste did not look visible at the current viewport.
- A second HTML image attempt was made before counting editor figures.
- Later scrolling revealed duplicate images; one duplicate had to be removed before draft-save.
- Clicking near the footer opened preview instead of entering tags once.

Corrective lessons:

- After any Tistory image insertion attempt, count visible figures or scroll to the intended anchor before trying another method.
- Never combine clipboard-image paste and HTML/data-URL image insertion in the same editor unless figure count is confirmed unchanged at zero.
- If duplicate images appear, remove the extra image with a single selected-image cut/delete action and recount before tags or save.
- For tags, click only a visible tag input or placeholder. Do not use bottom-left footer clicks as tag entry unless the tag input is visibly active.
- If preview opens while trying to enter tags, close preview and re-locate the visible tag input before continuing.
