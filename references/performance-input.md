# Performance Input

Use this when the user provides actual blog results. Do not invent metrics.

## Daily Performance Input

Ask for or accept:

- Post URL or title.
- Platform: Naver Blog or Tistory.
- Published date.
- Post type.
- Main keyword.
- Views.
- Search inflow keywords.
- Likes, comments, saves, or shares if available.
- Average reading/engagement signal if available.
- Coupang Partners clicks.
- Coupang Partners conversion or revenue if available.
- Reader questions from comments or messages.

## Analysis Output

For each post, summarize:

- What likely worked.
- What likely limited performance.
- Whether the title, opening, layout, or topic should be repeated.
- Whether the topic belongs in a repeatable cluster.
- What to test next.

## Update Rules

Update `performance-log.md` with actual values only.

Update `style-memory.md` only if:

- A pattern repeats across multiple posts.
- The pattern is supported by real performance or repeated reader response.
- The update does not depend on copying another creator.

Update `affiliate-scoring.md` only if:

- A category repeatedly earns clicks or conversions.
- A category repeatedly gets views but no buyer action.
- Return-risk, price volatility, or trust risk becomes clear.

## Practical Metrics

Use these as directional signals, not absolute truth:

- High views + low clicks: topic is interesting but purchase intent may be weak.
- Low views + high clicks: title or exposure may be weak, but buyer intent is strong.
- High comments/questions: make follow-up posts and FAQ sections.
- Repeated search inflow keyword: build a topic cluster.
- Affiliate clicks without conversion: improve product fit, price bands, or final recommendation.
